01

The setup

Three verticals — Food, Quik, Shops — and one question that decides whether a shared personalization layer is worth building: when a user is cold on the surface being ranked but active elsewhere, does their other behaviour help?

The agent profiles the log, writes down falsifiable claims with the slice each applies to and the minimum effect that counts as support, runs the smallest comparison that could refute each one, then lets the verdicts choose the next round. It prunes families that fall out of contention, raises catalogue-health guardrails, and stops when it runs out of questions rather than when the leaderboard stops moving.

Protocol, identical for every arm: per-user temporal leave-one-out, last interaction held out. Every arm ranks the same candidate pool with the same already-seen masking, applied by the evaluator rather than the model, so no arm can win by filtering harder. Primary metric NDCG@10; every comparison paired at user level with a 2,000-sample bootstrap 95% CI.

02

The verdict ledger

Each interval is the 95% CI for relative lift. The dashed line is the bar that hypothesis committed to before running. An interval entirely past the bar is support; entirely short of it is refutation; straddling it means the data cannot separate the two.

Most claims did not survive. That is the expected shape of an honest bake-off — and H3-kg is reported as underpowered rather than null because only 25 of 1,382 tail rows were ranked in the top-10 by either arm, so the comparison could not have detected the effect it was looking for.

Where the two datasets disagree

The same hypothesis, the same code, two logs. This is the result the whole exercise exists to produce.

Held

With transfer genuinely present in the generative process, the method recovers it. This validates the method, not user behaviour.

amazon_xvert · real, 35,229 users
−1.9%
95% CI [−7.3%, +3.3%] · bar +5% · n = 12,715
Refuted

On real cross-category purchases the interval excludes the +5% bar entirely. Graph-walk transfer does not deliver the lift it delivers in simulation.

Both runs cleared the no-harm guardrail, so transfer costs single-surface users nothing — it simply does not pay on this real log. The honest reading: the mechanism works when the signal is there, and on Amazon cross-category co-purchase the signal is too weak to clear a 5% bar. A marketplace with genuinely shared intent across verticals is a different question, and the simulator shows what the answer would look like if it were.

Scope of the Amazon run: rounds 1–2 completed (nine baselines and the transfer ablation, 35,207 evaluation rows). Rounds 3–4 — the transformer, the fusion ranker and session adaptation — were cut short on CPU budget, so those four hypotheses carry simulator evidence only. Stated here rather than left for a reader to notice.

Leaderboard

careem_sim. Coverage and novelty sit next to accuracy on purpose: a model that wins by serving the same head items to everyone is a catalogue-collapse risk, not a ranking win.

The transformer lands below the popularity floor on overall NDCG. With a median history of 13 events there is little sequence for attention to exploit, and its top-10 covers 7.5% of the catalogue against the graph walk's 70%. Reported as a refutation, not omitted.

05

How the agent spent its budget

Rounds are not a fixed schedule. Each one is chosen from the previous round's verdicts.

The stopping rule, in its own words

“Round 3 did not move the leaderboard, but ['fusion', 'session_adaptation'] still test untested mechanisms, so the run continued.”

A plateau rule alone would have ended the run at round 3 with the fusion and session-adaptation hypotheses never tested. A hypothesis-driven agent stops when it runs out of questions, not when a number stops moving.

Conflict the agent raised itself

Interleaving and the simulated A/B disagree in sign: +0.0991 per-slate preference against −6.4% CTR. Mean true utility of the full slate is lower for the challenger (+0.0067 against +0.0549).

The champion is better at placing the single next item near the top and worse at filling the other nine slots. NDCG@10 on one held-out item is not slate quality — and a readout that reported the offline win without naming this would have shipped a regression.

08

Run it

pip install -r requirements.txt

python -m autoexp --dataset careem_sim     # ~10 min, no downloads
python -m autoexp --dataset amazon_xvert   # real HF data, ~1GB once
python -m autoexp --dataset both --llm     # + Claude-written readout

streamlit run app.py                       # browse any completed run
python tests_smoke.py                      # the five bug regressions

Each run writes report.md, run.json (every hypothesis, verdict and statistic — the auditable log), leaderboard.csv and narrative.md. The LLM narrator is an upgrade, not a dependency: with no API key a deterministic narrator renders the same facts, which also makes the model's output diffable against a known-correct version of itself.

Data: McAuley-Lab/Amazon-Reviews-2023 (5-core, rating-only; Grocery → food, Health & Household → quik, Beauty → shops) plus a bundled multi-vertical simulator with known transfer strength. 25.8% of the 1.46M users in those categories buy across two or more of them.
